How it works

From launch to bear in five steps

The same flow the CatHouse prototype uses, with bears in place of cats.

┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│  LAUNCH  │──▶│   HOLD   │──▶│   SIGN   │──▶│  CLAIM   │
│ coin + N │   │ min amt  │   │ message  │   │ one bear │
└────┬─────┘   └────┬─────┘   └────┬─────┘   └────┬─────┘
     │              │              │              │
     ▼              ▼              ▼              ▼
 create + dev   balance read   proves you    random free
 buy, 1 tx      from chain     own wallet    slot, locked

   ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
   no keys leave the wallet · one bear per holder
  1. 1
    Launch the coinCreate the coin and the dev buy in one transaction, with the set size you choose.
  2. 2
    Holders connectA holder opens the site and connects a wallet.
  3. 3
    Sign a messageSigning proves the wallet is theirs. It costs no SOL and moves nothing.
  4. 4
    Check the balanceThe server reads the wallet’s balance on chain and compares it to the minimum.
  5. 5
    Claim a bearA random free slot is assigned and locked to that wallet.

How much supply does a set ask holders to hold?

If every pet is claimed, holders together must hold the set size times the minimum.

The server picks a random free slot, so a bigger set means lower odds of any one specific pet. A holder at the minimum gets one pet, never more.
